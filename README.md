# Taskflow — приложение для задач

Готовый фронтенд на HTML/CSS/JavaScript, REST API на Node.js + Express и база PostgreSQL.
Без Docker, CI/CD, Kubernetes, Nginx и облачных сервисов. Фронтенд отдаёт сам Node.js.

## Возможности

- Создание, редактирование и удаление задач с подтверждением.
- Статусы «В планах», «В работе», «Готово».
- Приоритеты, описание и срок выполнения.
- Поиск по названию/описанию, фильтр по статусу и общие счётчики.
- Адаптивный интерфейс на русском языке.
- Данные хранятся в PostgreSQL и сохраняются после перезапуска приложения.
- Проверка данных на сервере, параметризованные SQL-запросы, безопасный вывод текста.

Это однопользовательское локальное приложение без регистрации и разграничения доступа.
По умолчанию сервер слушает только 127.0.0.1. Не публикуйте его в интернете как многопользовательский сервис.

## Что нужно

Node.js 22 или новее, npm и установленный PostgreSQL. Интернет нужен для установки npm-зависимостей.
Версии можно проверить: `node -v`, `npm -v`, `psql --version`.

## Запуск на Ubuntu

### 1. Создать базу и отдельного пользователя

Если PostgreSQL ещё не установлен:

```bash
sudo apt update
sudo apt install postgresql
```

Откройте консоль PostgreSQL:

```bash
sudo -u postgres psql
```

Выполните в ней:

```sql
CREATE ROLE taskflow WITH LOGIN;
\password taskflow
CREATE DATABASE taskflow OWNER taskflow;
\q
```

Команда `\password` попросит придумать и дважды ввести пароль. Ввод не отображается.
Создавать пользователя и базу нужно только один раз. Используйте отдельную пустую БД для этого приложения.

### 2. Подготовить приложение

В терминале перейдите в распакованную папку `taskflow`:

```bash
npm ci
cp .env.example .env
nano .env
```

В `.env` укажите пароль пользователя БД в `PGPASSWORD`. Для пароля с символом `#` заключите всё значение в двойные кавычки. Сохраните файл: Ctrl+O, Enter; выйдите: Ctrl+X.
Остальные значения можно оставить как есть, если PostgreSQL работает на той же Ubuntu.
Настоящие пароли не пересылайте и не добавляйте в публичные репозитории.

### 3. Создать таблицу и запустить

```bash
npm run db:init
npm start
```

`db:init` создаёт таблицу и индекс, не удаляя существующие задачи. Это не универсальный инструмент обновления схемы.
Откройте **http://127.0.0.1:3000** в браузере на той же машине. Для остановки сервера нажмите Ctrl+C.

### Если Ubuntu находится в VirtualBox, а браузер — в Windows

Откройте `.env` и задайте `HOST=0.0.0.0`, затем перезапустите Node.js.
В настройках сетевого адаптера VirtualBox (NAT) добавьте проброс TCP:

- IP хоста: `127.0.0.1`
- Порт хоста: `3000`
- IP гостя: оставить пустым
- Порт гостя: `3000`

Откройте на Windows **http://127.0.0.1:3000**. Это позволяет пользоваться приложением с ноутбука без публикации в интернете. Для сетевого моста используйте IP Ubuntu только в доверенной локальной сети. Базу данных наружу открывать не нужно.

## API

| Метод | Адрес | Действие |
|---|---|---|
| GET | `/api/tasks` | Все задачи |
| GET | `/api/tasks?status=doing&q=linux` | Фильтрация и поиск |
| POST | `/api/tasks` | Создать задачу |
| PUT | `/api/tasks/:id` | Полностью обновить задачу |
| DELETE | `/api/tasks/:id` | Удалить задачу |

Тело для POST/PUT (Content-Type: application/json):

```json
{
  "title": "Изучить права в Linux",
  "description": "Разобрать chmod и chown",
  "status": "todo",
  "priority": "medium",
  "due_date": null
}
```

Все пять полей обязательны. Статусы: `todo`, `doing`, `done`. Приоритеты: `low`, `medium`, `high`.
Срок: `null` или дата `YYYY-MM-DD`. Название: 1–160 символов после обрезки пробелов, описание: до 4000.
Успешное создание возвращает 201, обновление 200, удаление 204. Ошибки имеют поле `error` и статус 400/404/413/500.

## Если не запускается

- `ECONNREFUSED`: PostgreSQL недоступен по PGHOST/PGPORT; проверьте, запущен ли он.
- `28P01`: неверный пользователь или пароль PostgreSQL.
- `3D000`: база из PGDATABASE не создана.
- `42P01`: выполните `npm run db:init`.
- `EADDRINUSE`: порт 3000 занят; поменяйте PORT в `.env`, например на 3001.
- Ошибка `--env-file`: нужна Node.js 22 или новее.
- В браузере нет связи: терминал с `npm start` должен оставаться открытым; проверьте адрес и способ доступа к виртуальной машине.

В приложении нет демонстрационных задач: первые записи создаются через интерфейс.
